Choosing the next tests for Brakes India

The problem

Every new brake design has to be tested on a rig, and that takes time. A model that predicts the test result would save tests, but only where it can be trusted, and nobody knew where that was.

Role
Led the analysis
Lab
ADOPT Lab, IIT Madras
Client
Brakes India, part of the TVS Group, Chennai
Parts
Brake calipers and master cylinders

The idea

I held out entire groups of similar designs and looked at where the predictions broke down. That gave us a way to prioritise the next tests.

1How I tested the predictions

Brakes India, part of the TVS Group, is one of India's largest brake manufacturers. Its engineers use test rigs to measure how hydraulic brake components behave. I compared regression models on that data.

I compared linear models, tree ensembles and small neural networks because we needed to know whether a more flexible model would help on unfamiliar designs. I also compared SHAP with permutation importance to see which input effects appeared consistently across the analyses.

A random split can put very similar designs in training and testing. I used K-means on the design inputs alone, then held out each cluster in turn. That tests the situation the engineers actually face when they try a combination unlike the ones they've already measured. Most targets scored below 0.5, and some scores were negative.

0.94–0.96R² on a random split
< 0.5R² for most targets when a whole cluster of designs is held out

I checked whether poorly predicted groups coincided with sparsely sampled parts of the design space. The errors often appeared where the existing tests covered only a narrow range. That gave the team specific regions to sample in the next round.

For responses the model handled well, I used interpretable self-organising maps. The map places similar designs near each other. Colouring the same grid by an input and then by the test result lets an engineer see where changes in the two tend to coincide.
